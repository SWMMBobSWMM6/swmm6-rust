# Upstream notes

These are things in OpenSWMM 6 (swmm6_rel @ 88329d6) that looked wrong or odd during the translation. The translation keeps every one as written, so results stay identical; this list is for the upstream team. Each entry quotes the code as it stands.

| # | Where | What | Can it change a run? |
|---|---|---|---|
| U1 | `math/MathExpr.cpp` `tokenize` | A lone `.` starts a "number", and `std::stod` throws `std::invalid_argument`. Nothing on the path from `ControlEngine::addExpression` catches it, so `EXPRESSION E1 = 2 + .` aborts the process (code-review deck IO-41_point). Code: `t.value = std::stod(s.substr(start, i - start));` | Yes: it aborts |
| U2 | `data/SubcatchData.hpp` `erase_at` | Does not erase `gage_name`, `snowpack_name`, `old_ponded_depth` or `washoff_vout1`; the list goes from `e(outlet_name);` to `e(gage);`. After an erase those four columns are out of step with the rest. | Only through the edit API (deleting a subcatchment) |
| U3 | `data/GageData.hpp` `erase_at` | Does not erase `station_id`, `rain_units`, `file_first_date`, `file_last_date`, `file_periods_precip` or `rain_series`; the header's own comment admits it. | Only through the edit API |
| U4 | `data/SubcatchData.hpp` | `sweep_now` and `sweep_last_date` are never sized, erased or shrunk by any method; `resize_coverage` sizes only `coverage` and `sweep_last_swept`. | Only if some later code indexes them unsized (to be checked when street sweeping is translated) |
| U5 | `data/SubcatchData.hpp` `resize` | `outlet_name`, `snowpack_name` and `gage_name` are `resize`d (old entries kept) while every other column is `assign`ed (cleared). | Only on a second `resize` of a populated store |
| U6 | `data/LinkData.hpp` `erase_at` | Does not erase `time_last_set`, `slot_volume`, `stat_slot_vol_dt`, `stat_vol_dt`, `stat_peak_slot_share` or `stat_time_slot_above`. | Only through the edit API |
| U7 | `data/LinkData.hpp` `reserve_to` | `r(stat_flow_class);` reserves `un`, where the array holds `un * N_FLOW_CLASSES` (compare `stat_lstep_bin_time`, reserved at `un * N_LSTEP_BINS`). | No (capacity only) |
| U8 | `data/LinkData.hpp` `resize` | `pump_curve_name.resize(un);` keeps old entries where the other columns are `assign`ed; `stat_pump_periods.assign(un, 0.0);` assigns a double to a `vector<long>`. | Only on a second `resize` of a populated store |
| U9 | `data/LinkSubtypes.hpp` `ConduitData::erase_at` | Leaves the five `gw_*` columns unerased (the doc comment says so). | Only through the edit API |
| U10 | `data/NodeSubtypes.hpp` `set_node_type` | Zeroes `storage_area` before the same-type early return, so setting STORAGE again on a storage node still clears its area: `if (t != NodeType::JUNCTION && ui < nodes.storage_area.size()) nodes.storage_area[ui] = 0.0;` (the differential shows it: area 7 becomes 0). | Only through the edit API |
| U11 | `data/NodeSubtypes.hpp` `set_node_type` | `shifted = true;` follows `switch (old)` even when `old` is JUNCTION with a row, a state that should not exist. | No |
| U12 | `data/InfraData.hpp` `InletUsageStore` | `add_row` does not grow the stat columns, but `erase_row` erases from them. | Only through the edit API |
| U13 | `data/NodeSubtypes.hpp` `erase_node` | `drop(storages) \|\| drop(outfalls) \|\| drop(dividers);` drops only the first matching row. | No, if a node has one subtype row, as it should |
| U14 | `core/ErrorCodes.hpp` / `.cpp` | Code 635: the header comment says `Inlet %s cannot be used with the cross section of %s`, the table says `Inlet %s cannot be used with the cross section of its host.` (the translation follows the table). | No (wording) |
| U15 | `core/ErrorCodes.cpp` | Code 131, `"the following links form cyclic loops in the drainage system:"`, has no `%s`, so the name is dropped and a detail follows with no closing period. Warning 108 holds a bare `%` (`"(5% of the section top width)"`), which is harmless unless a caller ever passes it to printf as a format. | No |
| U16 | `hydraulics/XSectLookup.hpp` `lookup_exact` | Reads past the end of the table when n is 2, or 3 with x ≥ 0.5: `... * (t[i] / 2.0 - t[i + 1] + t[i + 2] / 2.0);`. The value it reads is whatever follows the table in memory. In the translation, the read panics. | Only for tables of 2 or 3 entries; the built-in tables are longer |
| U17 | `hydraulics/XSectLookup.hpp` | The fast path is gated by `#ifdef SWMM_XSECT_FAST_LOOKUP` (CMake's `OPENSWMM_FAST_XSECT_LOOKUP` defines it), but `lookup_fast` is compiled outside that guard, and only a test calls it when the macro is off. | No |
| U18 | `input/handlers/NodesHandler.cpp` | Ponded area is the one field read with `strtod` (`area = std::strtod(tok[6].c_str(), &end);`), so it alone accepts hex (`0x10` is 16), a leading `+` and leading spaces; every other number goes through `from_chars`. | Only on unusual input |
| U19 | `input/handlers/LinksHandler.cpp` | Outlet type detection is case-sensitive: `bool is_tabular = (type_str.find("TABULAR") != std::string::npos);`, so `tabular/depth` reads as FUNCTIONAL/HEAD, while keywords elsewhere are case-insensitive. | Yes, for a lower-case outlet type |
| U20 | `input/handlers/TablesHandler.cpp` | A new curve with no type word raises ERROR 205 naming its first x value, then still creates the curve with the previous curve's type (`current_idx = ctx.tables.add(current_name, current_type);`). | No (the run stops on the error) |
| U21 | `input/handlers/*` usage tails | `if (v < lo \|\| v > hi)` lets NaN through a range check. | Only with a `nan` token in the input |
| U22 | `input/handlers/SpatialHandler.cpp` | The comment says a line holding a quote "falls back to the owned tokenizer — behaviour is identical either way", but the two tokenizers differ: the view tokenizer drops empty CSV fields (`C2 ,,9`). | Only on quoted coordinate rows with empty fields |
| U23 | `input/handlers/UserFlagValuesHandler.cpp` | An out-of-range number leaves the value at zero (`ROUGHNESS_ADJ 1e400` gives 0.0) with no message. | Yes, silently, on such input |
| U24 | `input/handlers/HydrologyHandler.cpp` [GWF] | A literal like `1e999` or `2e-310` passes the strict `std::strtod` check, then MathExpr's `std::stod` throws `out_of_range`, and the user sees "internal: expression rejected by the engine parser" with column −1. | Error message only |
| U25 | `input/handlers/CatchmentHandler.cpp` | `ctx.gages.interval_sec[idx] = static_cast<int>(interval_secs + 0.5);` gives INT_MIN for a NaN or huge interval. | Only on such input |
| U26 | `input/handlers/HydrologyHandler.cpp` [GROUNDWATER] | An empty optional token `""` becomes 0.0, not MISSING, because `parse_double_strict("")` succeeds. | Yes, for a quoted empty optional field |
| U27 | `data/TableData.cpp` `validate_table` | `if (tbl.empty()) {` tests `x`, which `table_open_file` never fills, so every file opened through this path fails with ERROR 601: the file-backed table branch cannot succeed. | Yes, if anything relies on file-backed tables through this API |
| U28 | `data/TableData.cpp` | Rows are counted with `char buf[1024];` and read with `char buf[2048];`, so a line over 1,023 bytes is counted twice (a 5,000-row file of long lines reports 5,050, and its last boundary holds 119 rows, not 128). | Only for very long lines |
| U29 | `data/TableData.cpp` | `bool is_csv = has_named_columns(tbl.column_ids);`: a CSV whose header is "Date,1,2" loads its cache as .dat, and every lookup returns 0. | Yes, for numeric column names |
| U30 | `data/TableData.cpp` | `tbl.last_boundary = tbl.first_boundary;` for a small file, so every small ascending file draws WARNING 102. | Warning only |
| U31 | `data/TableData.cpp` | The format `"%d-%d-%d %d:%d:%d"` turns "2020-01-01T01:00" into midnight, and a year of "4294969316" reads as 2020 (`%d` through strtol, truncated). | Yes, for ISO "T" times |
| U32 | `hydraulics/XSectKernels.hpp` rect_round_getRofY | `return 0.5 * xs.r_bot * (1.0 - std::sin(theta1)) / theta1;`, inherited from legacy; probably meant to be `1 - sinθ/θ`. | Yes: hydraulic radius of RECT_ROUND near the bottom |
| U33 | `hydraulics/XSection.cpp` FILLED_CIRCULAR | `xs.s_bot = getWofY(xs, xs.y_bot);` reaches a branch that adds y_bot again, so the width is taken at 2·y_bot/(D+y_bot). | Yes: FILLED_CIRCULAR bottom width |
| U34 | `hydraulics/XSectKernels.hpp` invLookup | In the declining-top branch, `i = n_items - 2/-3` is always followed by the `i >= n - 1` return, so its interpolation is dead code. | No |
| U35 | `hydraulics/XSectKernels.hpp` powerfunc_getRofA | The guard `a <= 0.0` lets NaN through to the perimeter loop, which never ends when `0.02*y_full == 0`. | Hang on degenerate input |
| U36 | `hydraulics/XSection.cpp` | getSofA and getRofA call each other without end for DUMMY or unknown shape codes when a > 0 or a is NaN. | Hang on such input |
| U37 | `hydraulics/XSectBatch.hpp` | `build(const SimulationContext&)` is declared but never defined. | No |
| U38 | `hydrology/LidNode.cpp` readTreatment | Reads rows with `std::istringstream stream(line);` rather than the Tokenizer, so a comment line kept in the section becomes "Invalid [LID_LAYER_TREATMENT] row", and quotes and commas are not handled. | Yes: a commented deck is refused |
| U39 | `hydrology/LidNode.cpp` | `if (treatment::validate(rule.expression, error, col) != 0 \|\|` accepts built-in names only, so a pollutant reference (`TSS`, `R_TSS`) is rejected, and co-treatment cannot be reached from a deck. | Yes: the feature is unreachable |
| U40 | `hydrology/LidNode.cpp` readRichards | Finds the control with `ctx.lid_names.find(t[0])`, then re-reads with `in >> name >> tag;`, so a quoted name with a space fails as a material row. | Only for such names |
